# IRIS-T SLM 自动部署与雷达操作

Windows Python 项目，使用屏幕图像识别及键鼠输入。界面模板按中文、1920×1080 校准，其他分辨率和布局需要重新适配。

安装依赖：`python -m pip install -r requirements.txt`。
公开仓库包含程序和裁剪后的识别模板，不包含运行日志、完整游戏截图或录像。
部分回归测试依赖本地私人截图；没有对应截图时自动跳过。

## 从主页面开始一局

```powershell
python deploy_test.py --from-hangar
```

主显示器1920×1080、中文界面。在主页面先手动设置对局模式和IRIS-T载具，
保持与录像相同的阵容布局（IRIS-T在第一格且已选中），退出弹窗和菜单。
切回游戏按F8开始。程序不修改阵容或付费设置，也不主动切换载具卡片。

流程：Enter匹配 → 等待识别IRIS-T选车页和加入战斗按钮 → 等3秒并再次确认
页面仍就绪 → Enter部署 → 等出生HUD稳定 → 等10秒让队友离开 → 两台发射车
部署 → 等15秒 → 切车放两个弹药箱，各等5秒 → 切回雷达车 → 字母C+R
打开雷达 → 目标操作。--from-hangar自动启用preview和engage。

匹配等待最多600秒，出生等待最多120秒。超时留截图并停止，不重复按Enter。
可配置 --match-timeout、--spawn-timeout、--selection-delay、--spawn-wait。
开始页面由使用者在机库按F8确认，程序识别机库、战果及已适配弹窗。
错误载具或不同布局可能导致等待超时；离线检查不能保证所有实机情况均正常。

选车页识别使用左侧重生点与雷达工作模式标签，并检查IRIS-T及加入战斗按钮；
不再依赖底部会被自动开始倒计时替换的文字。已覆盖用户提供的正式对局倒计时截图。

--from-hangar 现在持续循环：匹配 → 部署 → 雷达操作 → 阵亡返回基地 → 战果页 → 下一局。
按F10停止，不设总时长。雷达页丢失后进行最多180轮恢复检查，连续识别到选车界面后按Esc，
识别并点击返回基地；适配资料卡遮挡，必要时点击空白处关闭资料卡再打开菜单。
确认框出现则点击“是”，没有确认框则等待返库。随后最多等待120秒，连续确认战果页
出现才按Enter开始下一次匹配。未知页面停止，不反复发送Enter。
--radar-only 和 --engage 仍只执行当前一局，不自动重新匹配。
出生确认后启用全阶段阵亡检测，覆盖等待队友离开、放置、冷却、切车及雷达操作。
每约0.3秒检查选车/战果界面，阶段截图也检查；资料卡遮挡同样识别。
检测到后中断当前操作，确认选车页后返库；--from-hangar继续下一局。
F10、失焦时的输入异常及其他未确认阵亡的错误仍停止，不自动重启。

## 从场景内开始

```powershell
python deploy_test.py --mode preview             # 只部署并进入雷达
python deploy_test.py --mode preview --engage    # 部署后继续目标操作
python deploy_test.py --radar-only              # 已打开雷达，单独目标操作
python deploy_test.py --from-hangar --dry-run   # 打印完整计划，不发送任何输入
```

F8开始，F10停止。切出游戏暂停，返回游戏按F8恢复；按键/鼠标按住期间失焦
则释放输入并停止。重跑前手动恢复相应初始状态，不能从中途盲目重跑部署。
雷达阶段不设持续时间，按F10手动停止；失焦或异常状态仍按原规则暂停或停止。

## 部署

先看近处地面，根据红绿预览搜索。第二辆保持第一辆的俯仰先横移，失败再
上下搜索。弹药箱在切车后重新调整视角。绿色稳定两帧后左键按住0.2秒松开。
发射车结合HUD变化检查结果；弹药箱在放置模式下重复左键尝试，每个位置最多两次，再移动搜索。
每次点击后检查Alt+E图标相对点击前变暗、颜色减少且放置提示消失，连续两帧通过后立即停点。
确认进入冷却后仍等待5秒再切车，不把恢复彩色当成再次放置的信号；建造完成仍未独立确认。
无有效预览则停止。没有自动驾驶或避障。
雪地弹药箱增加淡色轮廓判定：仅在明亮中性背景且掩蔽模式提示可见时启用，
检查准星附近连续淡绿色区域；淡红色仍可供预览诊断；实际弹药箱尝试不再依赖轮廓颜色，以放置模式和图标变化为依据。

--search-step 900 水平步长；--look-down 1200 初始下压；--pitch-step 600
俯仰搜索步长；--click-hold 0.2 左键保持；--cooldown 15 发射车完成后等待；
--build-wait 5 弹药箱点击后等待。鼠标计数不是角度，依赖游戏灵敏度及非反转Y轴。

## 雷达目标

使用用户预先开启的筛选。编号逐位识别，模板已覆盖数字0–9，
支持多位编号（包括19）及其星号；不同UI布局尚未覆盖。
新增样本来自用户雷达截图：4、8来自编号列，5、6、7来自同列表的距离、速度、方位列。
这些跨列样本尚需对应编号的实际截图验证，并非所有数字均已覆盖选中/未选中状态。
型号不参与判断。首次遇到有星目标跳过，无星进入候选；本轮第一发后出现星号仍补第二发。
无星号目标立即进入攻击候选，不受上一轮30秒计时限制。
仍带星号的目标，上一轮第二发输入完成30秒后允许再打两发。
短暂丢失不会提前清除计时，消失的目标不会被点击。

根据浅色行确认目标选中。随后右键双击一次，等待0.5秒，再右键双击一次，
两轮之间不重新左键选取。列表重排或短暂消失保留已确认的选中状态；
若识别到选中其他编号则停止。多个符合条件的目标轮换，星号消失后可以立即补射。
发射输入次数不等于实际发射数，尚未校验导弹数量、命中或击杀。

## 检查和记录

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

runs/时间/保存本地事件日志及阶段截图，包括列表变化、选中前后和发射后。
模板位于assets/；match_entry.py识别进入对局的阶段；radar_targets.py识别列表。
离线测试不能代替不同地图和正式对局的验证。

正常任务完成也会进入下一局：识别任务完成与确定按钮后按Enter；研发弹窗出现时点击分配研发点，确认主页面的加入战斗按钮和科技树后再按Enter匹配。阵亡返库后的研发弹窗使用相同处理。同一识别页面只发送一次操作，未知页面等待至超时后停止。

默认启用平滑变速放置操作：转视角采用先加速后减速，水平搜索每步分成60%–75%的寻找动作和余下的小幅调整，每段后检查放置条件；总搜索范围与俯仰规则保持一致。切车/搜索稳定等待、出生等待和部署冷却仅增加小幅随机时间，不缩短原下限；左键保持时间增加0–0.04秒。使用 --fixed-motion 恢复原固定移动与节奏。此功能不包含队友离开识别或地形理解。

自动启动：`python deploy_test.py --from-hangar --auto-start`，启动后等待5秒，请在此期间切回游戏；到时仍验证前台游戏窗口，不额外叠加 --start-delay。不加 --auto-start 仍由F8启动。F10停止、失焦后的F8恢复和guided模式的步骤确认保持不变。

匹配出现“缺少符合要求的载具型号：地面载具”弹窗时，识别并点击确定，等待3秒后在已识别的主页面重新匹配；每次错误重置匹配等待超时，不限制该错误的重试次数，F10仍可停止。不会点击切换游戏模式或更换载具。其他未知错误仍按原超时处理。
